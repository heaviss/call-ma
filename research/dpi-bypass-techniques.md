# Приёмы обхода DPI из GoodbyeDPI и аналогов: что из этого доступно браузеру

Вопрос: [#6](https://github.com/heaviss/call-ma/issues/6). Продолжение
[ресерча #3](https://github.com/heaviss/call-ma/blob/research/ru-signaling-channels/research/ru-signaling-channels.md).
Дата исследования — 2026-11-04. Замеров из РФ автор не делал.

Метки: **[V]** — проверено по первоисточнику (README, документация, исходный тикет);
**[I]** — вывод, прямого подтверждения нет.

## Коротко

1. Все приёмы GoodbyeDPI, zapret, ByeDPI и SpoofDPI работают ниже уровня, доступного
   странице: подделка TTL, контрольной суммы и SEQ, порядок и границы TCP-сегментов, IP-фрагментация.
   Нужен драйвер (WinDivert), NFQUEUE с root или хотя бы локальный SOCKS-прокси. Из
   WebSocket, fetch и WebRTC ни один из них не воспроизвести. **[V]**
2. Против двух из трёх блокировок из #3 эти приёмы бессильны даже с установленной
   утилитой. Блокировку STUN по IP:порту и мобильный белый список по CIDR они не обходят: zapret прямо пишет, что
   при блокировке по IP «автономный обход невозможен». **[V]**
3. Заморозку после ~16 КБ к зарубежным хостингам локальная утилита иногда снимает, подставляя
   в ClientHello SNI из белого списка. Подтверждения есть только в виде отчётов пользователей. **[I]**
4. У заморозки есть браузерный аналог обхода. Она считает данные на одно TCP-соединение, поэтому
   помогает переоткрывать WebSocket до исчерпания лимита. Это и есть единственный приём из
   этого класса, который стоит реализовать в call-ma. **[V]** для механизма, **[I]** для применимости к Trystero.
5. Установка утилиты как опция: технически работает только на Windows, Linux и Android и
   требует прав администратора. Пользователь — нетехнический абонент в РФ, ему
   это не по силам. Опция годится лишь как ссылка «если знаете, что делаете». **[I]**

## Приёмы по одному

Источники: README
[GoodbyeDPI](https://github.com/ValdikSS/GoodbyeDPI) (последний push 2026-01-19),
[zapret](https://github.com/bol-van/zapret) и [zapret2](https://github.com/bol-van/zapret2)
(оба обновлены 2026-11-04), [ByeDPI](https://github.com/hufrea/byedpi) (2026-11-01),
[SpoofDPI](https://github.com/xvzc/SpoofDPI) (2026-10-16). Все прочитаны 2026-11-04.

| Приём | Что делает с пакетами | Где описан | Доступен из браузера | Помогает против блокировок из #3 |
|---|---|---|---|---|
| Фейк с малым TTL (`--set-ttl`, `--auto-ttl`, `--ttl`) | Перед настоящим запросом шлёт поддельный, TTL которого истекает после DPI, но до сервера. DPI видит фейк, сервер — нет | GoodbyeDPI, ByeDPI `--fake`, zapret `--dpi-desync=fake` [V] | Нет: страница не задаёт TTL ни для TCP, ни для UDP [V] | Против IP-блокировок нет [V]. Против заморозки — возможно, с фейковым SNI из белого списка [I] |
| Фейк с неверной контрольной суммой или SEQ (`--wrong-chksum`, `--wrong-seq`, `--md5sig`) | То же, но сервер отбрасывает фейк по контрольной сумме, старому SEQ или опции TCP MD5 | GoodbyeDPI, ByeDPI, zapret [V] | Нет: нужен raw-сокет [V] | Как у фейка с TTL |
| Разбиение TCP-сегментов (`-e`, `--native-frag`, `--split`, `multisplit`) | Режет первый пакет, обычно ClientHello или HTTP-запрос, на несколько TCP-сегментов, часто прямо по SNI | GoodbyeDPI `--frag-by-sni`, ByeDPI `--split 0+s`, zapret [V] | Нет: границы сегментов выбирает стек ОС [V] | Нет. Автор разбора заморозки пишет, что фрагментация внутри одного соединения не помогает: цензор считает суммарный объём [V] |
| Обратный порядок сегментов (`--reverse-frag`, `--disorder`) | Шлёт части не по порядку; ByeDPI отправляет первую часть с TTL=1, ОС досылает её после SACK | GoodbyeDPI, ByeDPI [V] | Нет [V] | Нет [I] |
| Разбиение на TLS-записи (`--tlsrec`) | Делит ClientHello на две TLS-записи внутри одного TCP-потока | ByeDPI [V] | Нет: запись формирует TLS-стек браузера [V] | Нет [I] |
| OOB-данные (`--oob`, `--disoob`) | Вставляет байт с флагом URG, который DPI склеивает с потоком, а сервер — нет | ByeDPI [V] | Нет [V] | Нет [I] |
| Правка HTTP-заголовков (`hoSt`, смешанный регистр, лишний пробел) | Ломает парсер `Host:` в DPI | GoodbyeDPI `-r -s -m -a`, ByeDPI `--mod-http`, zapret [V] | Нет: `Host` — запрещённый заголовок fetch, а у WSS он внутри TLS [V] | Нет: наш трафик целиком внутри TLS [V] |
| Отброс RST и редиректов от пассивного DPI (`-p`, `--ip-id`) | Фильтрует пакеты DPI с IP ID `0x0000` и `0x0001` | GoodbyeDPI [V] | Нет [V] | Нет: ТСПУ — активный DPI, он не шлёт RST, а молча отбрасывает пакеты [V] |
| Фейки и паддинг UDP/QUIC (`fake`, `udplen`, `ipfrag2`, `-q`) | Фейковый UDP-пакет перед настоящим, раздувание UDP-пейлоада, IP-фрагментация UDP. zapret умеет распознавать STUN, QUIC, WireGuard и Discord Voice | zapret `--filter-l7=stun`, ByeDPI `--udp-fake` [V] | Нет: WebRTC не даёт управлять UDP-пакетами [V] | Нет: STUN Google в РФ блокируют по IP:порту, а не по сигнатуре (#3). zapret пишет, что `fake` для UDP помогает только против stateful DPI [V] |
| Подмена DNS (`--dns-addr` на Yandex DNS `77.88.8.8:1253`) | Обходит отравление DNS у провайдера | GoodbyeDPI [V] | Частично: страница может сама сходить в DoH через fetch, но WebSocket и TLS всё равно пойдут по имени хоста [I] | Нет: в #3 DNS не отравлен, блок идёт по IP [V] |
| Подмена SNI на домен из белого списка | ClientHello несёт SNI вроде `ozon.ru`, а соединение идёт на свой сервер | Не GoodbyeDPI, а прокси: dumbproxy, VLESS+REALITY ([net4people #490](https://github.com/net4people/bbs/issues/490#issuecomment-3899961786), 2026-02-13) [V] | Нет: SNI равен хосту из URL, а `Host` нельзя переписать (domain fronting недоступен) [V] | Против заморозки к Hetzner и DigitalOcean — да, у Ростелекома и Yota в феврале 2026 [V, один отчёт]. Против мобильного CIDR-списка — нет [V] |
| Разнос данных по нескольким TCP-соединениям | Каждое соединение передаёт меньше лимита | [net4people #490](https://github.com/net4people/bbs/issues/490), описание тикета, 2025-06 [V] | **Да**: закрывать и переоткрывать WebSocket [V] | Против заморозки — да [V]. Против CIDR-списка и блокировки STUN — нет [V] |

## Блокировки из #3 и что против них работает

### STUN по IP:порту

zapret в разделе «Когда это работать не будет» прямо называет случай «если блокировка
осуществляется по IP», а в разделе про Россию добавляет: «применяются блокировки некоторых диапазонов
ip адресов (автономный обход невозможен)». **[V]** Значит, никакая утилита не вернёт
`stun.l.google.com:19302`. Решение — сменить серверы на работающие по OONI, как предложено в #3.

### Заморозка после ~16 КБ

Описание [net4people #490](https://github.com/net4people/bbs/issues/490) (автор hyperion-cs,
тикет открыт в июне 2025, текст прочитан 2026-11-04):

- соединение замерзает, когда сервер стоит в зарубежном дата-центре (Hetzner, DigitalOcean и т. п.),
  а объём в рамках **одного TCP-соединения** превышает ≈15–20 КБ **[V]**;
- upd5: на деле порог — около 25 пакетов в любую сторону, и это касается **и TCP, и UDP** **[V]**;
- фрагментация TCP и IP внутри одного соединения не помогает, а разнос по нескольким
  соединениям помогает **[V]**;
- у цензора есть белый список SNI (upd3), и подставленный SNI из него снимает заморозку **[V]**;
- upd4: местами применяют и CIDR-белый список, тогда без промежуточного узла с «белым» IP
  обойти нельзя **[V]**.

Пользователи сообщают, что zapret снимал этот вид блокировки
([2025-10-27](https://github.com/net4people/bbs/issues/490#issuecomment-3450393806)), но
стратегию не приводят. **[I]** Механизм, скорее всего, такой: фейковый ClientHello с SNI из белого списка
и малым TTL. ByeDPI делает это через `--fake -1 --fake-sni`, zapret — через `--dpi-desync=fake`
с `tls_mod=rndsni` или своим блобом. **[I]**

Что из этого доступно браузеру:

- **Переоткрывать сокет раньше лимита.** Сигналинг call-ma маленький: SDP с кандидатами занимает
  единицы КБ. Если считать отправленные и полученные байты и сообщения и переоткрывать MQTT или
  трекер-сокет, например, каждые 15–20 пакетов или ~10 КБ, заморозка не наступит. **[I]** Оговорки:
  TLS-рукопожатие со
  сертификатом съедает несколько КБ и пару пакетов из лимита; keepalive MQTT тоже считается пакетами. **[I]** Как
  часто Trystero шлёт анонсы в MQTT, нужно проверить отдельно. **[I]**
- Обнаружение уже есть в виде чекера
  [hyperion-cs/dpi-checkers](https://github.com/hyperion-cs/dpi-checkers), который работает
  прямо из браузера. **[V]** Значит, и call-ma может распознать заморозку по тайм-ауту, как
  предлагалось в #3.
- UDP-вариант порога (upd5) касается медиа через TURN в зарубежном дата-центре. Прямой
  P2P между двумя домашними IP под критерий «зарубежный дата-центр» не подпадает. **[I]**

### Мобильный белый список

[net4people #516](https://github.com/net4people/bbs/issues/516): «no matter what SNI you 'spoof',
it won't connect to, say, your own server … because it's an IP whitelist». **[V]** Ни один
DPI-приём это не обходит, нужен узел с IP из белого списка. Без своей инфраструктуры остаётся
ручной обмен SDP через Max или VK, как в #3.

## Браузерные «встроенные» средства

- **ECH (Encrypted Client Hello).** Включается браузером, а не страницей, и только если в DNS
  (HTTPS-запись) у сервера есть конфигурация ECH. Firefox включил ECH по умолчанию в 2023
  ([net4people #280](https://github.com/net4people/bbs/issues/280)). **[V]** В РФ ECH к Cloudflare
  блокируется с 2024-11-05 по связке SNI `cloudflare-ech.com` + расширение ECH; блокировку
  официально подтвердил ЦМУ ССОП ([net4people #417](https://github.com/net4people/bbs/issues/417)). **[V]**
  Даже работающий ECH прячет только SNI. Против блоков по IP и объёму он бесполезен. **[I]**
- **Большой ClientHello с постквантовым обменом ключей** в Chrome и Firefox сам выходит за
  размер одного сегмента. Это естественная фрагментация, но ТСПУ её собирает:
  блокировки в РФ работают и при ней. **[I]**
- **DoH из страницы.** fetch к DoH-резолверу даёт IP, но WebSocket и WebRTC TURN по TLS всё
  равно открываются по имени, а голый IP в URL ломает проверку сертификата. Для STUN можно
  указать IP напрямую, но STUN блокируют по IP, а не по DNS. **[I]**
- **WebRTC-медиа.** DTLS-отпечаток у браузера штатный, такой же, как у любых браузерных звонков.
  В 2021 году Россия блокировала Snowflake (Tor поверх WebRTC) именно по отпечатку DTLS
  нестандартной библиотеки pion, а в 2024-11 — уже без явного отпечатка: данные просто переставали идти
  после рукопожатия ([net4people #422](https://github.com/net4people/bbs/issues/422)). **[V]**
  Касается ли это обычного браузерного WebRTC между двумя домашними абонентами, данных нет. **[I]**

## Установка утилиты у абонента в РФ

| Утилита | Платформа | Права | Чем покрывает наш трафик | Замечания |
|---|---|---|---|---|
| GoodbyeDPI | Windows 7–11 | Администратор, драйвер WinDivert [V] | TCP (HTTP/TLS), блокирует QUIC (`-q`) [V] | Последний push 2026-01-19, стратегии под ТСПУ 2025–2026 не обновлялись [I] |
| zapret / zapret2 | Linux, OpenWrt, Windows, частично macOS [V] | root или WinDivert [V] | TCP и UDP, включая STUN [V] | Самая полная. Сборка Flowseal для Windows — один `.bat`, но антивирусы удаляют WinDivert как RiskTool [V] |
| ByeDPI / ByeByeDPI | Linux, Windows; Android без root (ByeByeDPI) [V] | Без root (SOCKS-прокси) [V] | Только то, что идёт через прокси. Браузерный WebRTC UDP через SOCKS не проксируется [I] | Единственный вариант для Android-телефона |
| SpoofDPI | macOS, Linux; iOS и Android — нет [V] | Обычный пользователь (HTTP-прокси) [V] | Только TCP через прокси [V] | — |
| iOS | — | — | Ни одна утилита не поддерживает [V для SpoofDPI, I для остальных] | — |

Вывод **[I]**: утилита помогает только против одной из трёх блокировок — заморозки — и только на десктопе
или Android. Ставить её должен абонент в РФ, а от него нельзя ожидать настройки стратегий,
исключений в антивирусе и прав администратора. Если абонент всё же готов что-то
установить, проще и надёжнее поставить VPN с «белым» SNI или IP. Это вне рамок call-ma. В
интерфейсе разумно ограничиться ссылкой на справку, без интеграции.

## Что делать в call-ma

1. Ничего из GoodbyeDPI/zapret не переносить: в браузере это невозможно.
2. Сделать ротацию сигнальных WebSocket раньше ~16 КБ или ~20 пакетов на соединение —
   единственный переносимый приём. Сначала замерить, сколько байт и пакетов Trystero MQTT и torrent
   тратит за сессию. В комплекте с детектором заморозки из #3.
3. Не держать медиа-TURN в зарубежных дата-центрах, где UDP тоже замерзает после ~25 пакетов (upd5).
4. Для мобильного белого списка DPI-обхода нет. Оставить ручной обмен SDP через Max или VK.
