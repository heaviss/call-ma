# More Trystero Transports + Direct-Mode E2E Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Race two more zero-config Trystero transports (Nostr, IPFS/Waku) alongside the existing MQTT+BitTorrent, add a Playwright e2e test that drives the existing `DirectAdapter` QR/link fallback across two real browsers, wire it into CI, and refresh the README. Also brings a few stale devDependencies forward first, since new tooling (Playwright's ESLint plugin) is about to be added on top of them.

**Architecture:** No new production architecture — `TrysteroAdapter` already loops over a generic `transports` array, so the two new transports are pure wiring in `src/main.js`. The e2e layer is a second, independent test runner (Playwright) living in its own `e2e/` directory so it never collides with Vitest's `src/**/*.{test,spec}.js` glob.

**Tech Stack:** Vite, Vitest, `@trystero-p2p/*`, Playwright (`@playwright/test`), ESLint flat config, GitHub Actions.

## Global Constraints

- Node.js ≥ 18, npm ≥ 10 (from `package.json` engines / README).
- Prettier config in `.prettierrc`: printWidth 100, singleQuote, semi, trailingComma "all". Run `npm run format` if a step's formatting drifts from this.
- ESLint flat config (`eslint.config.js`); "use the strictest linters and rules available" (CLAUDE.md) — but **do not** bump `eslint` past `^9.39.4` or `eslint-plugin-unicorn` past `^65.0.1` in this plan: `eslint-plugin-vitest@0.5.4` (latest published) hard-caps its peer range at `^8.57.0 || ^9.0.0`, and `eslint-plugin-unicorn@66+` requires `eslint@>=10.4` — these two constraints are mutually exclusive right now. Revisit when `eslint-plugin-vitest` ships ESLint 10 support.
- Vitest tests live under `src/**/*.{test,spec}.js` only (`vitest.config.js` `test.include`). Playwright tests live under `e2e/**/*.js` only — never inside `src/`.
- Every task ends in its own commit. Run `npm run lint` and the relevant test command before each commit.

- [ ] **Step 2: Wire both into the transports array**

Edit `src/main.js` — full new contents:

```js
import { joinRoom as mqttJoinRoom }    from '@trystero-p2p/mqtt';
import { joinRoom as torrentJoinRoom } from '@trystero-p2p/torrent';
import { joinRoom as nostrJoinRoom }   from '@trystero-p2p/nostr';
import { joinRoom as ipfsJoinRoom }    from '@trystero-p2p/ipfs';
import { initPwa } from './pwa.js';
import { initApp } from './app/controller.js';
import { getMqttRelayUrls, getTorrentRelayUrls } from './shared/config/relays.js';

initPwa();

if (globalThis.window !== undefined && globalThis.document !== undefined) {
  try {
    const searchParams = new URLSearchParams(globalThis.window.location.search);
    const transports = [
      { joinRoom: mqttJoinRoom,    relayUrls: getMqttRelayUrls(undefined, searchParams) },
      { joinRoom: torrentJoinRoom, relayUrls: getTorrentRelayUrls(undefined, searchParams) },
      { joinRoom: nostrJoinRoom },
      { joinRoom: ipfsJoinRoom },
    ];
    initApp({ document: globalThis.document, window: globalThis.window, navigator: globalThis.navigator, transports });
  } catch {}
}
```

Neither Nostr nor IPFS takes a `relayUrls` override here — Nostr ships its own large built-in public relay list when none is given, and the IPFS/Waku strategy has no such config knob at all (`defaultBootstrap: true` internally). Do not add `getNostrRelayUrls`/`getIpfsGatewayUrls` helpers to `src/shared/config/relays.js` — no requirement drives them (see spec's Non-goals).

### Task 4: Write the direct-connect e2e test

**Files:**
- Create: `e2e/direct-connect.spec.js`

**Interfaces:**
- Consumes: `playwright.config.js`'s `use.baseURL`/`launchOptions` from Task 3 (browser-level flags apply automatically; context-level `permissions` do **not** propagate to manually created contexts, so this test passes them explicitly — see Step 1 comment). Consumes the app's existing DOM contract: `#directBtn`, `#directCopyBtn`, `#directAnswerInput`, `#directConnectBtn`, `#logs` (all defined in `index.html`, wired in `src/app/controller.js`).
- Produces: nothing consumed by later tasks.

- [ ] **Step 1: Write the test**

Create `e2e/direct-connect.spec.js`:

```js
import { test, expect } from '@playwright/test';

const BASE_URL = 'http://localhost:5173';
// ponytail: browser.newContext() doesn't inherit playwright.config.js's `use.permissions` —
// only the default page/context fixtures do — so this test grants them explicitly.
const CONTEXT_OPTIONS = { permissions: ['camera', 'microphone', 'clipboard-read', 'clipboard-write'] };

test('two browsers connect via the direct QR/link fallback', async ({ browser }) => {
  const initiatorContext = await browser.newContext(CONTEXT_OPTIONS);
  const receiverContext  = await browser.newContext(CONTEXT_OPTIONS);
  const initiator = await initiatorContext.newPage();
  const receiver  = await receiverContext.newPage();

  await initiator.goto(`${BASE_URL}/?debug=true`);
  await initiator.locator('#directBtn').click();
  await expect(initiator.locator('#directCopyBtn')).toBeEnabled({ timeout: 10_000 });
  await initiator.locator('#directCopyBtn').click();
  await expect(initiator.locator('#logs')).toContainText('Direct link copied.');
  const offerLink = await initiator.evaluate(() => navigator.clipboard.readText());

  await receiver.goto(offerLink);
  await expect(receiver.locator('#directCopyBtn')).toBeEnabled({ timeout: 10_000 });
  await receiver.locator('#directCopyBtn').click();
  await expect(receiver.locator('#logs')).toContainText('Direct link copied.');
  const answerLink = await receiver.evaluate(() => navigator.clipboard.readText());

  await initiator.locator('#directAnswerInput').fill(answerLink);
  await initiator.locator('#directConnectBtn').click();

  await expect(initiator.locator('#logs')).toContainText('Direct connection established!', { timeout: 10_000 });
  await expect(receiver.locator('#logs')).toContainText('Direct connection established!', { timeout: 10_000 });

  await initiatorContext.close();
  await receiverContext.close();
});
```

This drives the exact same DOM affordances a real user would use — click the button, click copy, read the system clipboard, paste into the input, click connect — across two independent real Chromium contexts doing real `RTCPeerConnection` negotiation. No mocking.
